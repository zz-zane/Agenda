# 自动更新发布

更新源固定为公开仓库 https://github.com/zz-zane/Agenda 。私有 self-agenda 的 Release 不会触发客户端更新。

从 3.1.1 起，Windows 安装版使用 electron-updater：启动后30秒及每4小时检查最新正式版本，后台下载并校验SHA-512，在正常退出时安装；设置可关闭自动检查及退出安装，也可手动检查、下载完成后立即重启更新。只接受更高版本，不订阅预发布版本。检测失败可手动重试，不影响日历。

旧版（包括3.1.0）没有更新客户端，用户需要先手动安装一次3.1.1或之后版本；不能从服务端给旧客户端补上此能力。

## 每次发布

1. 同步提高 desktop/package.json 和 desktop/package-lock.json 的版本号（例如3.1.2）。
2. 在 Windows 运行 scripts/build-windows.py，生成 NSIS 安装包。
3. 在 **zz-zane/Agenda** 创建对应版本的正式 Release，附带以下同一次构建文件：
   - Agenda-Setup-版本-x64.exe
   - Agenda-Setup-版本-x64.exe.blockmap
   - latest.yml
4. 可另外附上源码 ZIP 与 SHA256SUMS.txt。将该正式 Release 设为 Latest。

不能只上传源码、仅推送Git提交或只替换exe；缺少latest.yml时客户端会显示更新源未提供自动更新文件。不要手工更改latest.yml中的文件名、size和sha512，不要混用不同构建的文件。GitHub公开下载不需要在客户端内置Token。

安装沿用原安装目录，业务数据仍保存在%LOCALAPPDATA%/Agenda/data。当前项目安装包未签名，SHA-512用于核对下载文件，不等同于发布者签名；以后配置代码签名后沿用electron-updater的签名校验。

测试包括真实electron-updater对隔离HTTP更新源的下载/校验、损坏文件拒绝、不降级及应用内安装状态/退出顺序。测试不执行伪造安装文件，不代替全新Windows实机升级验收。
